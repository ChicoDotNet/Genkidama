# KB-006

## Status

Proposed — pending owner approval.

## Goal

Define one canonical authoring and review standard for every Design Pattern page before scheduled automation begins filling the catalog.

## Scope

- Define the required pedagogical structure for a completed pattern page.
- Make problem, forces, intent, trade-offs, relationships, misuse and verification mandatory content.
- Require a fit-for-purpose Mermaid diagram rather than forcing every pattern into the same diagram type.
- Require honest Genkidama usage claims and verified repository links only.
- Define a binary Definition of Done and a weighted review rubric.
- Define an agent workflow suitable for incremental family-by-family completion after approval.
- Propose retrofitting `wiki/AbstractFactory.md` as the first golden reference page.

## Non-goals

- Do not rewrite any pattern page in this delivery.
- Do not change the global relationship map in this delivery.
- Do not reassign or reschedule either Genkidama automation in this delivery.
- Do not change Learn courses, runtime code, dependencies or generated applications.

## Approval gate

No pattern-filling automation should use this standard until the owner explicitly approves it.

After approval, the first content increment should bring `AbstractFactory.md` into compliance and use that reviewed result as the visual/content reference for the rest of the catalog.

## Validation

- The standard is self-contained and copyable by a scheduled agent.
- The Definition of Done rejects placeholders, dead/invented links and materially incorrect definitions.
- The standard remains consistent with `docs/philosophy/001-patterns-as-living-examples.md`: architecture comes first and patterns are not introduced merely to showcase them.
- No production or course behavior changes.
