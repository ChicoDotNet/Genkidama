# KB-006

## Status

**Approved by the owner on 2026-08-14.**

## Goal

Define one canonical authoring, implementation and review standard for every Design Pattern before autonomous catalog completion begins.

## Scope

- Define the required pedagogical structure for a completed pattern page.
- Make problem, forces, intent, trade-offs, relationships, misuse and behavioral verification mandatory.
- Require a fit-for-purpose Mermaid diagram rather than forcing every pattern into one diagram type.
- Require honest Genkidama usage claims and verified repository links only.
- Require an explicit applicability inventory for every Genkidama language target.
- Require one verified example in **every language where the pattern can be implemented meaningfully**.
- Treat language completeness as a set requirement (`every Applicable language has an example`), not as a test-coverage percentage.
- Treat `N/A` as a reviewed technical exception; lack of classes or OOP syntax is not sufficient justification.
- Define a binary Definition of Done and weighted review rubric including cross-language correctness and idiomaticity.
- Define one-pattern-per-PR autonomous delivery after approval.
- Establish `AbstractFactory.md` as the first golden reference to retrofit.

## Owner decisions

The owner approved the canonical template and strengthened its Definition of Done: a pattern is implemented only when every applicable language has a verified example.

Examples should be idiomatic rather than mechanical translations. Functional, prototype-based, logic, message-passing and other paradigms count whenever they can preserve the pattern's intent.

The owner also clarified the code/test coverage policy:

- **44% is sufficient as the approval floor** when relevant behavior and risks are protected;
- **44%–72.8% is fully acceptable**;
- coverage above 72.8% is welcome and is never penalized;
- **100% code/test coverage is not required**;
- delivery must not stall merely to chase a higher percentage once quality gates and meaningful behavioral tests are satisfied.

This test-coverage policy is separate from the requirement to provide an example for every Applicable language.

## Operating model

Catalog completion and Genkidama Learn are coordinated through the repository roadmap and `dev` integration branch.

- Course lane: approximately 80% advancing 0 → Junior courses and 20% checking compatibility with the pattern/Knowledge Base lane.
- Pattern lane: approximately 80% completing one pattern to the approved DoD and 20% checking compatibility with Learn.
- Both lanes integrate through `dev` and never merge or enable auto-merge.
- `main` is promoted by the owner when both lanes report a simultaneously stable integration state.

## Non-goals

- Do not rewrite a pattern page inside this standards delivery.
- Do not force a pattern into production architecture merely to showcase it.
- Do not change course pedagogy or runtime behavior here.
- Do not use coverage percentage as a vanity target.

## First content increment

Bring `wiki/AbstractFactory.md` into full compliance and use it as the reviewed golden reference. It remains in progress until its applicability table is complete and every Applicable language has a verified example.

## Validation

- The standard is self-contained and copyable by an autonomous agent.
- The DoD rejects placeholders, dead/invented links, materially incorrect definitions and incomplete language implementation sets.
- Every Applicable language must have a verified example before `validated`.
- Measurable code/test coverage of 44% or more is sufficient when relevant behavior is protected; 100% is explicitly not required.
- The standard remains consistent with `docs/philosophy/001-patterns-as-living-examples.md`: architecture comes first.
- No production or course behavior changes are introduced by KB-006 itself.
